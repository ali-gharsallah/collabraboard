# Lot L1 — Signal fiable · notes

## P-L1-1 — Runner CPSI : le faux-vert, cause racine et correctif

### Cause racine
`services/cpsi-server-py/run_tests.py` exécutait chaque test dans un `try/except` qui **capturait
toute exception**, l'imprimait comme `FAIL` et l'agrégeait dans un compteur — puis le script se
terminait **sans jamais appeler `sys.exit`**. Le processus rendait donc **toujours le code 0**, même
avec des tests rouges. Tout consommateur qui juge la santé de la suite par le **code de sortie**
(shell `set -e`, `&&`, orchestrateur) voyait « vert » quel que soit l'état réel.

En CI, cela était masqué par une garde de chaîne : `grep -q "### 20/20 suites vertes ###"`. Fragile
par nature — elle dépend d'un marqueur imprimé, pas du verdict du processus ; un consommateur hors CI
(ou une reformulation du grep) réintroduit le faux-vert silencieusement. C'est le constat de
`docs/audit/TEST_AUDIT.md` (« run_tests.py exits 0 even on failure; CI relies solely on a grep guard »).

### Correctif
1. **Propagation du code de sortie** — `run_tests.py` agrège désormais le nombre total de tests
   échoués et termine par `sys.exit(0 if total_ko == 0 else 1)`. Casser un assert dans n'importe quel
   bloc fait sortir le runner avec un code ≠ 0 (vérifié : injection dans `test_cpsi_bloc1.py` →
   `19/20`, exit 1).
2. **Canari de méta-vérification** — `services/cpsi-server-py/canary.py` contient un test
   **délibérément rouge**, HORS de la suite normale (nom sans préfixe `test_` ni suffixe `_test` →
   ni `run_tests.py` normal, ni un vrai `pytest` ne le collecte). `run_tests.py --canary` l'exécute
   et **doit** rendre un code ≠ 0. Ce canari garde la propagation elle-même contre toute régression :
   si `--canary` rendait 0 un jour, la propagation serait cassée.
3. **CI** — étape `5c` : `run_tests.py | tee` (le code de sortie du runner traverse le `pipefail`,
   la garde grep reste en second rideau). Nouvelle étape `5c-bis` : `run_tests.py --canary` **doit**
   échouer, sinon la CI est rouge (faux-vert de retour).

### Vérification (local, 2026-08-06)
| Commande | Attendu | Obtenu |
|---|---|---|
| `run_tests.py` | exit 0 · `20/20` | exit 0 · `20/20` |
| `run_tests.py --canary` | exit ≠ 0 | exit 1 |
| assert cassé dans bloc1 puis `run_tests.py` | exit ≠ 0 | exit 1 · `19/20` |
| après restauration | exit 0 | exit 0 |

Critère de sortie P-L1-1 atteint : casser volontairement un assert dans `test_cpsi_bloc1.py` fait
échouer la commande de CI ; le canari est vert en mode normal (non exécuté) et rouge sur demande.
